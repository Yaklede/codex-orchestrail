# 0.3.0 직접 실행·선택적 위임 검증

## 변경한 구조

기본은 현재 메인 모델의 직접 실행이다. Astra를 출발점으로 권장하되 사용자의 모델·추론 선택은 유지한다. 작은 작업에는 setup·run·계획·상태 조회·하위 에이전트를 강제하지 않는다. 판단을 마친 뒤 구현량과 독립적인 부모 작업이 충분할 때만 위임한다.

추적 작업에서는 `begin`이 시작·계획·예약을 한 트랜잭션으로 처리하고 `finish`가 남은 검증·완료를 처리한다. 기본 `status`는 현재 계획·제약·최신 근거만 반환하며 과거 로그는 `detail:true`로 조회한다. 진단 로그와 실제 작업 변경의 revision을 나누되, 기존 `expectedRevision` 동작과 v1 로그는 보존했다.

회귀 테스트 53개가 통과했다. 새 테스트는 로그로 인한 허위 충돌, 실제 계획 변경 충돌, 기존 로그 읽기, idle 무상태 동작, 긴 이력의 출력 제외, begin 실패 시 롤백, 실패·오래된 근거·실행 중인 작업자의 완료 차단을 포함한다.

## 1. 작은 작업: 같은 Astra high로 비교

같은 시작 커밋·명세·공개 테스트와 사전에 고정한 평가 39개를 사용했다. Astra 단독 후 Orchestrail 직접 경로를 한 번씩 실행했다. 두 실행 모두 **39/39**를 통과했다.

| 방식 | 총토큰 | 일반 입력 | 캐시 입력 | 출력 | 추론 출력¹ | 시간 | 참고 Standard credits² |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Astra high 단독 | 112,032 | 21,760 | 87,040 | 3,232 | 144 | 123.1초 | 11.6560 |
| Astra high + 직접 경로 | 114,280 | 27,344 | 84,096 | 2,840 | 102 | 115.0초 | 12.4884 |

총토큰은 **2.01% 증가**, 참고 가중 비용은 **7.14% 증가**했다. 캐시가 있으니 추가 비용을 무시해도 된다는 결과가 아니다. 이 실행에서는 하위 에이전트와 `.orchestrail` 상태가 생성되지 않았고, 예전 강제 위임 경로의 12.7배 토큰 증가가 직접 경로에서 재현되지 않았다. 실행 경로 자체가 달라졌으므로 이를 같은 위임 기능의 90% 절감이라고 해석하지 않는다.

¹ 추론 출력은 출력의 일부다. 총토큰 = 일반 입력 + 캐시 입력 + 출력이며 중복 합산하지 않는다. cache-write input은 모두 0이었다.

² [공식 Standard 요율](https://learn.chatgpt.com/docs/pricing#token-rates)을 2026-09-15 확인해 적용한 참고값이다. Astra는 백만 토큰당 일반 입력 250·캐시 입력 25·출력 1,250 credits, Sol은 100·10·500을 적용한다. 실제 청구액, Fast 모드 요율, 구독 주간 차감량은 측정한 것이 아니다.

집계: [직접 경로 JSON](../benchmarks/results/2026-09-15-direct-v03.json).

## 2. 큰 작업: Astra 단독과 Astra 판단 → Sol 구현

우선순위·지연 실행·재시도·취소·종료 상태·리포트·입력 불변성을 요구하는 큐 라이브러리로 비교했다. 명세와 평가 **61개를 두 실행 전에 고정**했으며 동일한 시작 커밋과 평가 해시를 확인했다.

| 방식 | 전체 작업 완료 | 사후 소스 평가 | 관측 총토큰 | 일반 입력 | 캐시 입력 | 출력 | 시간 | 참고 Standard credits |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Astra high 단독 | 완료 | 61/61 | 98,693 | 24,058 | 69,376 | 5,259 | 182.5초 | 14.32265 |
| Astra high 판단 → Sol high 구현 | **주간 기준으로 중단** | 중단 시점 61/61 | **312,490 이상 관측** | 61,992 | 240,384 | 10,114 | 중단까지 184.1초 | **22.04531 이상 관측** |

위임 실행은 계정 주간 표시 45%에서 자동 중단됐다. Sol의 종료와 Result 수집은 확인했지만 부모의 최종 검증·완료 처리가 끝나지 않았다. 공식 부모 `turn.completed` 사용량이 없으므로 **완료된 실행의 총량은 null**로 남겼다. 위 표의 부분 사용량은 이 실험 소유 부모·자식 기록에서 마지막 누적 관측을 한 번씩 합친 값이며, 미관측 진행 중 요청의 사용량은 남아 있을 수 있다.

| 중단 시점까지의 구성 | 총토큰 | 참고 Standard credits |
| --- | ---: | ---: |
| Astra 부모 | 155,489 | 13.97545 |
| Sol Builder | 157,001 | 8.06986 |

부분 관측만으로도 완료된 Astra 기준 대비 총토큰 **3.17배**, 참고 비용 **1.54배**였다. 완료 품질·최종 비용 비교를 끝낸 것은 아니지만, 이 실행이 이미 쓴 비용을 제외하고 절감 사례로 처리할 수 없다. **Astra가 판단한 뒤 Sol에 위임하면 자동으로 더 싸진다는 가설은 이번에도 뒷받침되지 않았다.**

실제 연결은 `begin` → 예약된 Sol 시작 → Result 수집까지 확인했다. 네이티브 자식 종료와 관련 실행 프로세스 부재를 확인한 뒤 로컬 run을 paused로 기록했다. 강제 재실행이나 후속 모델 호출은 하지 않았다. `finish` 성공·실패·충돌 동작은 로컬 회귀 테스트로 검증했으며, 이 중단 실행을 전체 네이티브 완료 성공으로 표기하지 않는다.

사후 감사에서 CLI SubagentStart의 transcript_path가 자식에 속한다는 점을 예산 감시기에 반영했다. 부모 경로를 덮어쓰지 않고 자식 실행 중에도 별도로 감시하도록 수정하고 회귀 테스트를 추가했다. 이번 중단 자체는 관측 임계값으로 정상 작동했다. 향후 중단 결과에는 완전한 총량과 구분한 부분 관측도 자동 보존한다.

집계: [위임 비교 JSON](../benchmarks/results/2026-09-15-queue-v03.json).

## 결론과 사용량 경계

- **현재 권장 기본값: Astra를 포함한 사용자가 선택한 메인 모델의 직접 실행.** 플러그인은 모델·추론 설정을 자동 변경하지 않는다.
- 위임은 충분한 독립 작업이나 다른 운영상 이점이 있을 때 선택한다. 비용 절감은 약속하지 않는다. 이 큐보다 큰 실제 작업에서 손익분기점을 확인하려면 별도의 예산 안에서 반복 비교가 필요하다.
- 이번 수정·준비·분석과 모델 검증을 포함한 계정 표시는 **43% → 45%**였다. 이 2%p를 벤치마크만의 차감량으로 해석하지 않는다. 45% 도달 후 추가 실험은 시작하지 않았다.
- 직접 처리 경로의 과도한 관리 절차는 제거했지만, 위임 자체의 인계·부모 검토 비용은 남는다. 같은 결과에 가장 싼 방식이라는 주장을 제품 설명에 넣지 않았다.

## 측정 한계

- CLI 0.154.0, macOS, Node 22.14.0에서 각 조건을 한 번씩 실행했다. 순서·서버 캐시를 통제하지 않았으며 편차나 일반 절감률을 추정하지 않는다.
- 직접 경로는 하위 에이전트를 금지하는 조건이다. 플러그인 자체의 최소 추가 비용을 확인하며 자동 라우팅의 판단 정확도를 평가하지 않는다.
- 스킬을 임시 플러그인 파일에서 명시적으로 읽었다. 실제 앱 스킬 선택기의 로딩 비용과 같다고 보장하지 않는다. 직접 실행 후 YAML 설명 필드의 인용부호를 고쳤으며 최종 패키지는 별도 검증했다. 런타임·스킬 해시는 개발 실행별로 남겼다.
- 테스트 통과는 해당 명세의 제한된 동등성 기준이다. 모든 작업의 결과 품질이 같다는 뜻은 아니다. 소스 검토도 병행했다.
- 계정 주간 표시는 이 메인 대화의 구현·분석과 다른 활동을 포함한다. 무변화가 무료라는 뜻이 아니며 토큰을 주간 %로 환산하지 않는다.
- 부모와 모든 관측 하위 대화의 누적 토큰을 각각 한 번 합산한다. 원본 대화·계정 식별자는 공개하지 않는다. 계측은 설치 플러그인의 일반 기능에 추가되지 않았다.
